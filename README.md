# AutoVPN

Актуальная разработка ведётся только в `main`. Текущий срез: **V3G / 0.1.7**
с типизированным запуском выбранного узла, проверкой DNS-ответов, отменой чтения
дочерних процессов и владением ресурсами при очистке.
Единая точка продолжения — `docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`.

**Исправлены подтверждение выхода Windows-процесса и освобождение исходных stdout/stderr.**
Исправленная регрессия прошла на Linux и Windows Server: по шесть полных серий
из 940 случаев. В настоящих Windows отменах зафиксировано, что managed
`HasExited=true` предшествует native signal; очистка теперь дожидается сигнала
того же дескриптора. Оба варианта с удержанным и закрытым дескриптором наблюдателя
прошли однократную проверку записи в `.exe`.

Первая версия новой проверки имела Linux assertion error; она исправлена с
учётом настоящего типа pipe stream. Все её отказы сохранены. Отдельный таймаут
вспомогательной RM-диагностики первого R1 Windows остаётся открытым наблюдением.
Причина прежнего исторического `0x80070020` не объявляется установленной только
на основании новой зелёной серии.

Приложение остаётся в разработке. Передача узла службе, системный TUN, защита
DNS/IPv6, восстановление сети и установщик ещё не приняты. Работающий канал
состояния не означает подключение VPN.

## Точки входа

- `docs/checkpoints/NATIVE_PROCESS_EXIT_OWNERSHIP.md`: текущие изменения, наблюдённый native signal gap, точные результаты двух ревизий и следующий шаг.
- `docs/evidence/NATIVE_PROCESS_EXIT_OWNERSHIP_VALIDATION.json`: 24 основных TRX, все новые наблюдения, обе серии secondary CI/labs, сохранённые ошибки и точные source manifests.
- `docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`: правила работы, история переноса, сохранённый V3H и порядок продолжения.
- `docs/checkpoints/WINDOWS_FILE_LIFETIME_DIAGNOSTICS.md` и одноимённый `docs/evidence/WINDOWS_FILE_LIFETIME_DIAGNOSTICS_VALIDATION.json`: прежний Windows-отказ, снимок до него и неполная поздняя RM-диагностика.
- `docs/checkpoints/VALIDATOR_CLEANUP_OWNERSHIP.md` и `docs/evidence/VALIDATOR_CLEANUP_OWNERSHIP_VALIDATION.json`: владение ресурсами при аварийной очистке и история прежних отказов.
- `docs/checkpoints/WINDOWS_PIPE_COMPLETION.md` и `docs/evidence/WINDOWS_PIPE_COMPLETION_VALIDATION.json`: отмена pipe-read при занятых рабочих потоках и диагностика резервирования портов.
- `docs/checkpoints/NODE_RUNTIME_ENTRY.md` и `docs/evidence/NODE_RUNTIME_ENTRY_VALIDATION.json`: запуск выбранного узла шести протоколов, Unicode и настоящие Windows runtime labs.
- `docs/evidence/CHAT_TRANSFER_VALIDATION.json`: первый проверенный срез переноса.
- `README_RUNTIME_PREPARATION_RU.md`, `docs/checkpoints/ENDPOINT_PREPARATION.md`, `README_V3G_RU.md`, `docs/checkpoints/V3G.md`, `docs/evidence/V3G_VALIDATION.json`: прежние реализованные этапы и их границы.
- `docs/branch-archive/inventory.json`: сохранённая история веток; архивные прототипы не включены в продукт.

Источник узлов: публичный каталог `igareck/vpn-configs-for-russia`.
Данные подписки недоверенные: это не готовый исполняемый профиль и не
свидетельство работоспособности узла. Пользовательский каталог не открывается
от SYSTEM; установленная служба пока предоставляет только статус.

## Сборка и проверка

SDK закреплён в `global.json`: .NET `10.0.112`; исследованный runtime — `10.0.12`.

```powershell
dotnet build AutoVpn.slnx -c Release '-p:Platform=Any CPU'
./scripts/test-v3f.ps1
```

Скрипт полной регрессии сохранён под именем V3F: он проверяет **940 случаев**
в шести сериях на каждой ОС, получает закреплённое ядро, проверяет хеш,
сохраняет каждый TRX и возвращает ошибку при любом непройденном прогоне.
TLS-диагностика включена. Пропуски допускаются только по точному списку ОС.

Реализация: `463048597a73977c43ba425b829a5bcb0e69f4bc`.
Исправленный проверенный исходник: `19196ebafa8d5a9697f465a275afb4a350d47098`,
основной [run 37561949766](https://github.com/alinescafs3mp-afk/vpn/actions/runs/37561949766).
Между ними изменились только новая платформенная assertion и checkpoint;
все production-файлы идентичны.

| ОС | Шесть полных серий: passed / failed / skipped |
| --- | ---: |
| Linux | 5496 / 0 / 144 |
| Windows Server 2025 | 5550 / 0 / 90 |

Все прежние 920 уникальных случаев сохранены. Добавлены 4 контроля владения
original readers, 14 проверок native waiter и 2 Windows сравнения observer handle.
Новые 20: **222 passed / 0 failed / 18 skips** в двенадцати сериях каждого исходника.
Сборки обоих исходников и ОС имеют ноль предупреждений и ошибок. Все 380 файлов
в каждом из четырёх основных source archives сверены по размеру, SHA-256 и Git blob.

На каждом исходнике 18 реальных отмен валидатора и 6 timeout-helper controls
наблюдают managed exit до native signal; новый барьер дожидается последнего.
Все 42 Windows `Write/None`, 24 Linux `Read/None` и 66 удалений fixture-каталога
за серию прошли. Снимки exact observer handle подтверждают состояние до операции.
Ни задержек перед файловой проверкой, ни повторных попыток записи не добавлено.
Сроки 20/5/3 секунды, 32 попытки портов, TLS/negative assertions и настройки
параллелизма сохранены.

Первый основной run `37561704528` сохраняет 24 Linux assertion failures после
успешного binary probe. Первый R1 run `37561704390` отдельно сохраняет Windows
`QUERY_TIMEOUT` в проверке RM; его причина остаётся открытой. Этот query по-прежнему
ограничен двумя секундами. История не заменена результатом исправленного исходника.

Все шесть workflow исправленного исходника прошли, attempt 1, без reruns.
V2/V3/R1 дополнительно проверили normal/native режимы, TLS/lifecycle и WPF smoke.
Runtime lab запустил шесть протоколов под настоящим standard-user primary token;
SCM/авторизация статусной службы проверены отдельно. Server 2022 прошёл на первом
исходнике; test/doc correction не входит в его trigger, и повторный запуск для неё
не заявлен. Полное разложение source, jobs, TRX, skips и artifacts находится в evidence.

Следующий ограниченный шаг — exceptional stdin ownership и фазовые наблюдения
двухсекундного диагностического helper, затем передача выбранного узла службе.
V3H остаётся отдельным сохранённым кандидатом. Привилегированный runtime и сеть
требуют самостоятельной приёмки после журналирования и восстановления состояния.

## Windows-пакет

В отдельной разработческой поставке запускается `desktop/AutoVpn.Desktop.exe`.
Архив самодостаточный, но не является установщиком или готовым VPN.
Текущие R1/V3 workflow собрали development-пакеты на `19196eb`; V2/V3/R1
проверили WPF на Windows Server. Сохранены API metadata и журналы проверки
идентичности файлов поставки. Большие бинарные архивы здесь не скачивались;
распакованный пакет отдельную приёмку не проходил.
Не запускайте лабораторную установку службы на рабочем компьютере,
не отключайте антивирус и проверку подписи драйверов.

Не повторяйте исторические одноразовые скрипты интеграции и консолидации.
Гроку остаются сборка/проверка, не незавершённая реализация.
