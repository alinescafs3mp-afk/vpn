# AutoVPN

Кандидат этой ветки: `README_V3C_RU.md`, версия 0.1.4. Добавлены отдельный канал состояния Windows-службы и диагностика в интерфейсе. В `main` остаётся проверенная база V3B. Установка службы и настоящий VPN не подтверждены; установочные скрипты в V3C не входят. Проверки: `docs/evidence/V3C_VALIDATION.json`.

## Исторический обзор исходной базы

Ниже сохранено описание первоначального среза. Для продолжения V3C используйте `docs/checkpoints/V3C.md`, а не прежние инструкции упаковки.

Клиент Windows для подключения через TUN. Источник узлов — публичный каталог [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia). Это чужие данные, не готовый профиль и не доказательство, что узлы работают.

**Это не выпуск.** На Linux собраны исходники, модульные тесты и самодостаточный архив `win-x64`. Туннель Windows, защита DNS/IPv6, установщик и восстановление сети на Windows не проверялись.

Аудит этого среза: `docs/AUDIT.md`. Папка `for_fix/` в корне пустая, кроме `.gitkeep`, и оставлена для директив Астры.

## Что уже есть в коде

- Разбор списков URI, Base64, Clash и JSON (Xray/v2ray) в каноническую идентичность узла.
- Учёт семейств источника и отказ принимать обрезанное дерево за полный каталог.
- Слияние: пустой текстовый файл не стирает узлы другого файла той же семьи; ответ 304 и ошибка загрузки не удаляют ещё живой узел.
- Выбор и ограниченное переключение без обхода страны, закрепления и политики безопасности.
- Брокер, который на этой системе не включает TUN и не сообщает «Подключено».
- SQLite-каталог с отказом хранить секреты без DPAPI. На Windows служба открывает этот каталог. Здесь служба держит каталог в памяти.
- Окно WPF на русском языке. Оно компилируется и отсюда не запускается.

## Сборка

Нужен SDK .NET `10.0.112` (`global.json`).

```bash
dotnet build AutoVpn.slnx -c Release
dotnet test AutoVpn.slnx -c Release
```

Для разделения обычных и нативных проверок используйте `scripts/test-v3.ps1`. Прямой запуск всех тестов требует закреплённого ядра и переменных R5/R6, которые задаёт `scripts/test.ps1 -Native`. Пропуски и отсутствие прогона не считаются успешной проверкой туннеля.

Архив для Windows собирается на машине разработчика и в git не входит. Контрольная сумма лежит в `docs/evidence/build-manifest.json` и в `artifacts/SHA256SUMS` после локальной сборки. Установщика нет.

## Установка

Готового установщика нет. Архив не регистрирует службу и не кладёт Mihomo или Wintun. Не отключайте проверку подписи драйверов и антивирус. Пока нет прогона на Windows, не используйте архив как рабочий VPN.

Восстановление сети описано в `docs/RECOVERY.ru.md`. Кратко: `autovpn-recovery` читает только свой журнал. На системе без проверенного сторожа он не снимает чужие и свои правила и не должен сообщать, что сеть очищена.
