# AutoVPN

Актуальная разработка ведётся только в `main`. Текущий срез: **V3G / 0.1.7**
с типизированным запуском выбранного узла, проверкой DNS-ответов, отменой чтения
дочерних процессов и диагностикой очистки/резервирования портов.
Разработка перенесена в новый чат 6 октября; единая точка продолжения —
`docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`.

**Добавлена диагностика отказа Windows после отмены; причина пока не установлена.**
Срез сохраняет обе ошибки тела теста и очистки, фиксирует состояние того же
файлового дескриптора до проверки и ограниченно запрашивает держателей файла.
Все 13 новых проверок прошли. Прежний отказ эксклюзивного открытия `.exe` снова
воспроизведён; теперь есть снимок до ошибки и результат Windows-диагностики.
Подробности — `docs/checkpoints/WINDOWS_FILE_LIFETIME_DIAGNOSTICS.md`.

**Предыдущая полная регрессия прошла на Linux и Windows Server.** Проверены отмена
чтения при занятых рабочих потоках и отдельные реальные запуски шести протоколов
под обычным пользователем Windows. Жизненный цикл установленной службы проверен
отдельно. Приложение остаётся в разработке:
Передача узла службе, системный TUN, защита DNS/IPv6 и восстановление сети
ещё не приняты. Работающий канал состояния не означает подключение VPN.

- `docs/evidence/WINDOWS_PIPE_COMPLETION_VALIDATION.json`: точные 12 TRX, 42 контрольных JSON, исходные артефакты, все семь workflow и отдельные Windows labs.
- `docs/checkpoints/NODE_RUNTIME_ENTRY.md`: новый вход запуска, закрытый набор параметров шести протоколов, Unicode и текущие отказы Windows.

- `docs/evidence/CHAT_TRANSFER_VALIDATION.json`: проверенная диагностика очистки, 12 полных прогонов, исходные артефакты и границы результата.
- `README_RUNTIME_PREPARATION_RU.md` и `docs/checkpoints/ENDPOINT_PREPARATION.md`: опубликованные изменения после V3G.

свидетельство работоспособности узла. Пользовательский каталог не открывается
от SYSTEM; установленная служба пока предоставляет только статус.

## Сборка и проверка

SDK закреплён в `global.json`: .NET `10.0.112`.

```powershell
dotnet build AutoVpn.slnx -c Release '-p:Platform=Any CPU'
./scripts/test-v3f.ps1
```

Существующий скрипт полной регрессии сохранён под именем V3F: он проверяет
920 случаев в шести сериях на каждой ОС, получает закреплённое ядро, проверяет хеш,
сохраняет каждый TRX и возвращает ошибку при любом непройденном прогоне.
TLS-диагностика включена. Пропуски допускаются только по точному списку ОС.

Текущий проверенный CI код: `97f8423ad5314037270024ace083a22061273cd6`, основной
прогон `37539642819`. Целостность исходников и evidence подтверждена; Windows
приёмка срока жизни файла остаётся **FAILED / OPEN**.

| ОС | Шесть полных серий: passed / failed / skipped |
|---|---:|
| Linux | 5394 / 0 / 126 |
| Windows Server 2025 | 5429 / 1 / 90 |

Все 920 уникальных случаев, включая прежние 907, сохранены. Новые 13 проверок:
132 passed / 0 failed / 24 платформенных skips в двенадцати сериях. Сборки обеих
ОС имеют ноль предупреждений и ошибок. Оба основных исходных архива содержат
по 375 точно сверенных файлов; два дополнительных source archives совпали с ними.

Windows iteration 2 снова получила `IO / 0x80070020` в прежнем однократном
`Write/None` после отмены. До операции зафиксированы выход процесса, оба EOF,
удаление input, `Complete=true`, возврат обоих `Dispose` и `IsClosed=true`
того же binary SafeFileHandle. Поздний Restart Manager не сообщил держателей
(`Incomplete=true`); его helper был завершён и очищен. Последующее единственное
удаление каталога fixture прошло. Причина ошибки открытия остаётся неизвестной;
наблюдения managed handle и поздний пустой RM не устанавливают её.

Сохранены все 42 прежних pipe JSON, 53 фактических финальных validator JSON,
271 запись о сроке жизни и 24 независимых контроля helper. У failed case есть
шесть исходных диагностических записей; запись об успешном открытии не подменена.
Детерминированные проверки удерживаемого test-host файла и остановки зависшего
query прошли по шесть раз. Все сроки, 32 port attempts, TLS/negative assertions
и настройки параллелизма сохранены. Перезапусков CI ради зелёного результата нет.

Все шесть остальных автоматических workflow прошли. V2/V3/R1 проверили обе ОС,
дополнительные TLS/lifecycle этапы и WPF smoke. Runtime lab запустил шесть
протоколов под реальным обычным primary process token. Статусная служба прошла
SCM/авторизацию на Server 2025 и 2022; её client checks используют impersonation.
Эти результаты не принимают TUN, публичную связность, установщик или Windows 11.

История двух предыдущих ревизий и их Windows/Linux отказов остаётся без изменений
в `docs/evidence/VALIDATOR_CLEANUP_OWNERSHIP_VALIDATION.json`. Следующий ограниченный
шаг — контролируемо проверить оставшийся интервал освобождения файла, включая
влияние отдельного process handle тестовой fixture. Это гипотеза, а не причина,
установленная текущим прогоном. Затем продолжается выбранный узел/служба; V3H
остаётся сохранённым отдельным кандидатом.

## Windows-пакет

В отдельной разработческой поставке запускается `desktop/AutoVpn.Desktop.exe`.
Архив самодостаточный, но не является установщиком или готовым VPN.
Текущие R1/V3 workflow собрали development-пакеты на `97f8423`; V2/V3/R1
отдельно проверили WPF на Windows Server. API metadata и журналы проверки
идентичности файлов поставки сохранены. Большие бинарные архивы здесь не
скачивались; сам распакованный пакет отдельную приёмку не проходил.
Не запускайте лабораторную установку службы на рабочем компьютере,
не отключайте антивирус и проверку подписи драйверов.

Не повторяйте исторические одноразовые скрипты интеграции и консолидации.
Гроку остаются сборка/проверка, не незавершённая реализация.
