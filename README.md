# AutoVPN

Актуальная разработка ведётся только в `main`. Текущий срез: **V3G / 0.1.7**
с типизированным запуском выбранного узла, проверкой DNS-ответов, отменой чтения
дочерних процессов и диагностикой очистки/резервирования портов.
Разработка перенесена в новый чат 6 октября; единая точка продолжения —
`docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`.

**Очистка валидатора и тестового сервера переработана; приёмка Windows пока не закрыта.**
Новый срез сохраняет владение ресурсами после неудачного ожидания и добавляет
15 проверок. Linux-регрессия прошла; на Windows обнаружены отказы доступа к
тестовой копии бинарника после отмены процесса. Держатель файла пока не установлен.
Подробности и все исходные результаты — `docs/checkpoints/VALIDATOR_CLEANUP_OWNERSHIP.md`.

**Предыдущая полная регрессия прошла на Linux и Windows Server.** Проверены отмена
чтения при занятых рабочих потоках и отдельные реальные запуски шести протоколов
под обычным пользователем Windows. Жизненный цикл установленной службы проверен
отдельно. Приложение остаётся в разработке:
Передача узла службе, системный TUN, защита DNS/IPv6 и восстановление сети
ещё не приняты. Работающий канал состояния не означает подключение VPN.

от SYSTEM; установленная служба пока предоставляет только статус.

## Сборка и проверка

SDK закреплён в `global.json`: .NET `10.0.112`.

```powershell
dotnet build AutoVpn.slnx -c Release '-p:Platform=Any CPU'
./scripts/test-v3f.ps1
```

Существующий скрипт полной регрессии сохранён под именем V3F: он проверяет
907 случаев в шести сериях на каждой ОС, получает закреплённое ядро, проверяет хеш,
сохраняет каждый TRX и возвращает ошибку при любом непройденном прогоне.
TLS-диагностика включена. Пропуски допускаются только по точному списку ОС.

Текущий проверенный CI код: `6f819b12f04b056bd40244f68f2f3a4df5891e3a`, основной
прогон `37506558777`. Результат приёмки: **FAILED / открыто расследование Windows**.

| ОС | Шесть полных серий: passed / failed / skipped |
|---|---:|
| Linux | 5334 / 0 / 108 |
| Windows Server 2025 | 5357 / 1 / 84 |

Все 907 уникальных случаев, включая прежние 892, сохранены. В Windows iteration 5
новый тест отмены дочернего процесса получил отказ исключительного открытия
копии бинарника на запись после подтверждённого выхода и проверки отчёта очистки.
Отдельный V3 Windows normal получил ошибку удаления каталога fixture; она могла
скрыть более раннюю ошибку тела теста. Причина удержания файла неизвестна.
Следующие V3 Windows native/lifecycle/WPF/package стадии не запускались.

Первая реализация `9fcb465` прошла основную регрессию, но отдельный V2 Linux normal
выявил `ETXTBSY` в проверке записи в executable. Linux-контроль уточнён: сначала
обязательный отказ `Read/None` при удерживаемом файле, затем успех того же вызова
после очистки. Windows-проверки записи/удаления сохранены. Перезапусков CI,
увеличения сроков или числа попыток ради успешного результата не было.

Все четыре архива двух ревизий содержат по 367 точно сверенных исходных файлов.
24 полных TRX пересчитаны; сборки имеют ноль предупреждений и ошибок. На каждой
ревизии проверены все 42 прежних JSON-контроля отмены. Новый набор содержит
54 JSON на первом коде и 53 из 54 на текущем: один тест упал до вывода записи.
Пропущенные данные не подменяются. Шесть Windows-проверок блокированного input,
удержания бинарника после выхода и явного успешного повторения очистки прошли
на каждой ревизии, сохранив исходный неуспешный результат валидации.

Оба текущих Windows labs прошли: VLESS, VMess, Trojan, Shadowsocks, Hysteria2 и
TUIC под обычным primary process token; отдельно — статусная служба и SCM с
проверкой pipe-доступа через реальные impersonated account tokens. V2/R1 WPF
smoke проверил отрисовку, повторное открытие и сохранение настроек. Эти результаты
не закрывают отказ отмены, публичную связность, TUN или приёмку Windows 11.

Следующий ограниченный шаг — сохранить обе ошибки тела теста/его очистки и
установить держателя файла в отдельной Windows-диагностике с прежними проверками
и сроками. Затем продолжается передача выбранного узла службе. Кандидат V3H
остаётся отдельным пакетом; исторические прогоны сохранены в прежних evidence.

## Windows-пакет

В отдельной разработческой поставке запускается `desktop/AutoVpn.Desktop.exe`.
Архив самодостаточный, но не является установщиком или готовым VPN.
Текущий R1 workflow собрал development-пакет; V2/R1 отдельно проверили WPF на
Windows Server. V3 Windows-поставка не запускалась после отказа normal suite.
Сам распакованный архив отдельную приёмку не проходил; его байты здесь независимо
не проверялись.
Не запускайте лабораторную установку службы на рабочем компьютере,
не отключайте антивирус и проверку подписи драйверов.

Не повторяйте исторические одноразовые скрипты интеграции и консолидации.
Гроку остаются сборка/проверка, не незавершённая реализация.
