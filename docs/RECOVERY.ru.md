# Восстановление сети AutoVPN

Инструмент: `autovpn-recovery`.

Журнал по умолчанию:

`%LocalAppData%\AutoVPN\effects.sqlite`

Можно передать другой путь первым аргументом. Инструмент читает только этот журнал. Чужие правила, маршруты и DNS он не трогает и не удаляет.

## Коды выхода

| Код | Смысл |
|---|---|
| 0 | Файла нет, либо открытых своих записей нет. Сеть не менялась |
| 2 | Журнал не прочитан и переименован в карантин. Записи не считаются снятыми. Сеть не менялась |
| 3 | Открытые записи есть, а сторож не подтвердил снятие. Сеть не менялась |

Текущий сторож ничего не устанавливает. Если в журнале есть открытые строки, код 3 — правильный результат: программа не врёт, что правила сняты.

Повторный запуск после кода 0 ничего не удаляет. Повтор после кода 2 не возвращает испорченный файл на место и не объявляет его пустым успехом.

## Если туннель когда-нибудь будет включён

Сначала запустите `autovpn-recovery` на одноразовой Windows-машине и убедитесь, что сняты только записи AutoVPN. Не запускайте разрушающую проверку через единственное соединение, которым вы управляете машиной.

Эта сборка не устанавливает фильтры, поэтому восстанавливать на Linux-хосте нечего. Не меняйте ради проверки маршруты и iptables этой машины.

## Чего нет

Установщика, регистрации службы и удаления службы нет. Архив неподписанный. Не отключайте защитник Windows и проверку подписи драйверов.
