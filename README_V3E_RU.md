## Изменения V3E

Теперь для запуска проверочного ядра резервируется один порт сразу для TCP и UDP. Проверяются разнесённые кандидаты, оба сокета удерживаются до передачи порта дочернему процессу. Это исправляет прежнее предположение «свободен TCP, значит можно запустить SOCKS с UDP». Передача между освобождением сокетов и запуском ядра всё ещё не атомарна.

Остановка ProbeWorker ожидает завершения принадлежащего ему процесса до очистки файлов. Одновременные вызовы очистки объединяются; неудачная попытка остаётся ошибкой и допускает повтор на том же объекте. Постоянно занятый файл не превращается в фиктивно успешное удаление. Отменённый до запуска запрос не создаёт процесс. Код TLS/HTTP, проверка сертификатов, SDK и хеш ядра не изменены.

Добавлены 13 тестовых случаев управления портами, процессами и файлами. Вместе с 12 перенесёнными случаями набор вырос с 486 до 511, включая прежние диагностические повторы протоколов.

В последней серии не повторились отказы резервирования портов и очистки нативного `cache.db`. Это ограниченное наблюдение, не доказательство устранения всех прежних тайм-аутов. ## Продолжение

Дальнейшие изменения только в `main`. Следующий узкий участок: остановка обработчиков stdout/stderr на Windows при одновременно живом соседнем процессе, с точной причиной и управляемым воспроизведением. Не увеличивать тайм-ауты и не проглатывать ошибку ради зелёного отчёта. После этого продолжить установленную Windows-службу и передачу выбранного узла.

В этой итерации не подтверждены установка службы, TUN, WFP, защита DNS/IPv6, восстановление после аварии/перезагрузки/сна. Новый исполняемый Windows-пакет в поставку V3E не включён. Сборка и испытания выполнялись в GitHub Actions, не в локальном окружении автора. Гроку остаются сборка и проверка, не незавершённая реализация.
