# Восстановление сети AutoVPN

Инструмент: `autovpn-recovery`.

Журнал по умолчанию:

`%LocalAppData%\AutoVPN\effects.sqlite`

Можно передать другой путь первым аргументом. Инструмент читает только этот журнал. Чужие правила, маршруты и DNS он не трогает и не удаляет.

## Коды выхода

| Код | Смысл |
|---|---|
| 0 | Файла нет и этот путь ещё не открывался: нет `.journal-seen`, `.recovery-unknown`, карантина и sidecar. Либо журнал прочитан и открытых своих записей нет. Сеть не менялась |
| 2 | Журнал чужой схемы оставлен на месте. Либо файл не прочитан: перед переносом пишется `.recovery-unknown`, затем файл и sidecar уходят в карантин. Либо файла нет, но путь уже открывался или рядом остались карантин либо sidecar. Записи не считаются снятыми. Сеть не менялась |
| 3 | Открытые записи есть, а сторож не подтвердил снятие каждой уникальной записи. Повтор одного и того же идентификатора не закрывает остальные. Сеть не менялась |

Текущий сторож ничего не устанавливает. Если в журнале есть открытые строки, код 3 — правильный результат: программа не врёт, что правила сняты.

Повторный запуск после кода 0 ничего не удаляет. Повтор после кода 2 снова выходит с кодом 2: файл чужой схемы остаётся на месте, маркер `.recovery-unknown` и `.journal-seen` не стираются, а файл из карантина не возвращается и не объявляется пустым успехом. Удаление `effects.sqlite` после того, как журнал уже открывали, тоже код 2.

## Если туннель когда-нибудь будет включён

Сначала запустите `autovpn-recovery` на одноразовой Windows-машине и убедитесь, что сняты только записи AutoVPN. Не запускайте разрушающую проверку через единственное соединение, которым вы управляете машиной.

Эта сборка не устанавливает фильтры, поэтому восстанавливать на Linux-хосте нечего. Не меняйте ради проверки маршруты и iptables этой машины.

## Чего нет

Установщика, регистрации службы и удаления службы нет. Архив неподписанный. Не отключайте защитник Windows и проверку подписи драйверов.
