## Implemented source

### Single process owner

`OwnedCoreSupervisor` implements `ICoreController`, `ICoreLiveness` and asynchronous disposal. It publishes ownership before a backend can start. Same generation/operation/profile callers share one start. The same owner cannot change its profile, and a second owner cannot start while the previous owner still has cleanup obligations. Canceling a duplicate waiter does not cancel the original caller. Canceling a stop waiter does not discard the stop task.

Stop-before-start fences that exact operation. Successfully cleaned operations cannot resurrect, while a different operation can reuse the same generation after cleanup, as required by a possible failover. Older generations cannot reappear after a newer generation. Tombstones are bounded to 4096 owners in the current generation; exhaustion requires a new generation instead of silently forgetting cancellation. Foreign stop requests do not retire or stop the active owner.

A backend stop exception retains the owner and permits another real stop attempt. A throwing cancellation callback does not waive cleanup. A claimed successful start with an already-dead process is rejected. An observed exit is represented as Exited with cleanup still pending, not a replayed Ready result. Process output and exception messages are not included in the supervisor's result/snapshot.

### Concrete runtime, deliberately not an installed VPN

`MihomoRuntimeProcess` validates a constrained generated non-TUN YAML profile, verifies the manifest-selected executable SHA-256 with an open read handle, creates a private per-attempt working directory, and starts that exact executable using an argument list rather than a shell. Windows elevated/administrator/SYSTEM, service-account and session-zero execution is refused. The Windows temporary directory has an explicit owner/SYSTEM ACL; Unix directory permissions are 0700. These platform behaviors are authored but NOT_RUN.

Both standard streams are drained without retaining raw text. Readiness requires the process to own both loopback listening ports and answer an authenticated `/version` request with the pinned core version. Redirects and proxy use are disabled for that controller request; its response is capped at 4096 bytes. This proves neither a proxy handshake nor a working traffic path, and never directly grants the UI Connected state.

Stop owns the process object, requests termination of its process tree, waits for process exit and pipe drain, then deletes its own directory and releases handles. Uncertain cleanup throws and remains represented. The implementation does NOT provide Windows Job Object lifetime, a broker-crash watchdog, SCM hosting, system crash recovery or proof of descendant containment. Those omissions are one reason TUN/elevated execution remain refused.

The private local SOCKS listener is not authenticated. Therefore it is restricted to this unprivileged development runtime and cannot be promoted into a persistent privileged multi-user endpoint. There is no new IPC operation accepting arbitrary YAML or a binary path.

### Profile and installation boundary

`RuntimeProfileContract` rejects any top-level TUN key, other listener types, non-loopback controller/listener endpoints, additional ingress keys, selected-profile persistence, extra DNS listener configuration, duplicate or non-scalar keys, merge keys, tags, anchors/aliases, multiple YAML documents and bounded-size/depth violations. The controller secret is excluded from default JSON and record text. This is a constrained generated-runtime contract, not a general safe importer or an authorization token.

`CoreInstallation` reads exactly one matching platform executable pin; missing/malformed/duplicate pins do not authorize an executable. It does not fetch latest binaries or accept a caller-supplied replacement hash. The packaged configuration is still same-owner installation input, not a completed privileged installation trust root.

### Broker integration

The console host now constructs the concrete supervisor rather than `RefusingCoreController`; however its actual Connect profile is still TUN, so that path remains refused. This is not a hidden conversion into a SOCKS-only VPN.

`TwoTargetProbeTransport.TargetIdentity` is a pure extraction of the existing V2 identity/validation algorithm. The host computes the required pair identity without creating network workers. It checks already-saved assessments and does NOT add a second, unbudgeted admission/probing loop. Revalidation remains with the existing maintenance owner.

`BrokerEngine` accepts an optional required target-set identity for backward-compatible test/internal construction; the concrete host always supplies it. Selection, final eligibility and standby acceptance retain this requirement. In-process confirmation also rechecks consent and target identity. A consent change during start invalidates the attempt even without a settings revision change. No external client can call the in-process confirmation method.

When a snapshot/state/confirmation observes that the owned process has exited, CoreRunning is cleared, the session is blocked and stale confirmation is refused. Resource ownership and actual protection remain until cleanup. This is on-read observation, not yet an autonomous event/status notification loop. It does not automatically complete a replacement/failover sequence.

`ShutdownAsync` closes new admission and waits for confirmed disconnect/owned cleanup. The console Ctrl+C and pipe-stop paths invoke it and report incomplete cleanup rather than claiming success. An outer deadline limits the caller's wait, not the underlying cleanup obligation. This is NOT an installed Windows service stop or a guarantee after forced process termination.

### Accurate protection state

The reducer now preserves the actual protection flag on VerifyFailed, CoreExited, HealthFailed and UplinkLost. An unprotected session does not acquire a fictional armed guard after an error. Broker failure messages no longer unconditionally claim that protection remains enabled.

## Still open, not delegated as implementation

- A coherent live catalogue authority / authenticated narrow runtime handoff. Separate UI and console `SqliteCatalogue` instances retain independent in-memory snapshots; this increment does not fix that stale-state problem.
- Installed SCM lifecycle, least-privilege owner/session authorization, binary/config installation integrity and OS-owned child lifetime.
- Actual protected TUN, WFP guard, DNS/IPv6 containment, traffic-path proof, safe crash/reboot recovery, installer/upgrade/uninstall.
- A fully owned active-runtime replacement sequence. The new supervisor correctly requires old cleanup first; the existing broker failover path is not yet adapted into a complete real-runtime replacement transaction.
- Autonomous process exit notifications, desktop status polling, and active-session consent revocation/disconnect across the future privileged boundary.
- Native runtime/ACL tests on Windows, regression execution, Windows UI and long-run soak.
- Existing audit gates, including unresolved historical TLS_REJECTED evidence and download/source-policy gaps, remain binding.
