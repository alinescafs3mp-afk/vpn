# AutoVPN

Актуальная разработка ведётся только в `main`. Текущий срез: **V3G / 0.1.7**
с типизированным запуском выбранного узла, проверкой DNS-ответов, отменой чтения
дочерних процессов и диагностикой очистки/резервирования портов.
Разработка перенесена в новый чат 6 октября; единая точка продолжения —
`docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`.

**Новый срез очистки валидатора и тестового сервера ожидает проверки в CI.**
Он сохраняет владение ресурсами после неудачного ожидания и добавляет 15 проверок.
Подробности — `docs/checkpoints/VALIDATOR_CLEANUP_OWNERSHIP.md`.

**Предыдущая полная регрессия прошла на Linux и Windows Server.** Проверены отмена
чтения при занятых рабочих потоках и отдельные реальные запуски шести протоколов
под обычным пользователем Windows. Жизненный цикл установленной службы проверен
отдельно. Приложение остаётся в разработке:
Передача узла службе, системный TUN, защита DNS/IPv6 и восстановление сети
ещё не приняты. Работающий канал состояния не означает подключение VPN.

## Точки входа

- `docs/checkpoints/CHAT_TRANSFER_2026-10-06.md`: актуальная база, правила работы, сохранённый V3H, незавершённые задачи и порядок продолжения.
- `docs/checkpoints/VALIDATOR_CLEANUP_OWNERSHIP.md`: новый срез аварийной очистки валидатора и тестового сервера; проверка CI ожидается.
- `docs/checkpoints/WINDOWS_PIPE_COMPLETION.md`: принятый срез отмены pipe-read, очистки и диагностики портов; результаты всех CI и оставшиеся границы.
- `docs/evidence/WINDOWS_PIPE_COMPLETION_VALIDATION.json`: точные 12 TRX, 42 контрольных JSON, исходные артефакты, все семь workflow и отдельные Windows labs.
- `docs/checkpoints/NODE_RUNTIME_ENTRY.md`: новый вход запуска, закрытый набор параметров шести протоколов, Unicode и текущие отказы Windows.
- `docs/evidence/NODE_RUNTIME_ENTRY_VALIDATION.json`: точные результаты обоих коммитов, 24 полных TRX, настоящие запуски под обычным пользователем и незакрытые отказы.
- `docs/evidence/CHAT_TRANSFER_VALIDATION.json`: проверенная диагностика очистки, 12 полных прогонов, исходные артефакты и границы результата.
- `README_RUNTIME_PREPARATION_RU.md` и `docs/checkpoints/ENDPOINT_PREPARATION.md`: опубликованные изменения после V3G.
- `README_V3G_RU.md`: история V3G, измеренные результаты, первая неудачная серия и ограничения.
- `docs/evidence/V3G_VALIDATION.json`: коммит, Git-дерево, прогоны и первичные артефакты.
- `docs/checkpoints/V3G.md`: историческая точка V3G; текущие задачи уточнены в checkpoint переноса.
- `docs/branch-archive/inventory.json`: сохранённая история прежних веток; архивные прототипы не включены в продукт.

Источник узлов: публичный каталог `igareck/vpn-configs-for-russia`.
Данные подписки недоверенные: это не готовый исполняемый профиль и не
свидетельство работоспособности узла. Пользовательский каталог не открывается
от SYSTEM; установленная служба пока предоставляет только статус.

## Сборка и проверка

SDK закреплён в `global.json`: .NET `10.0.112`.

```powershell
dotnet build AutoVpn.slnx -c Release '-p:Platform=Any CPU'
./scripts/test-v3f.ps1
```

Существующий скрипт полной регрессии сохранён под именем V3F: он проверяет
907 случаев в шести сериях на каждой ОС, получает закреплённое ядро, проверяет хеш,
сохраняет каждый TRX и возвращает ошибку при любом непройденном прогоне.
TLS-диагностика включена. Пропуски допускаются только по точному списку ОС.

Предыдущий проверенный код: `c8c43a7ffff95a235b248c6dc38b15e235b7ef78`, основной
прогон `37497048946`. Linux: 5250 passed / 0 failed / 102 skipped за шесть серий.
Windows Server 2025: 5268 passed / 0 failed / 84 skipped. Все 892 уникальных
случая и точные списки пропусков пересчитаны в каждом TRX; 362 файла обоих
исходных артефактов сверены по SHA-256 и Git blob. Сборки без предупреждений
и ошибок. Все семь workflow прошли с первой попытки, без перезапусков.

Последний срез добавил 26 случаев: отмена чтения при двух занятых worker в
отдельном процессе, сохранённый отрицательный контроль старого `Task.Delay`,
повторный вход в очистку, чтение валидатора и ограниченная диагностика портов.
Сроки ожидания, TLS-проверки, 32 попытки резервирования и параллелизм основных
тестов сохранены. Реальные Windows stdout/stderr отменялись за 5–7 мс в шести
изолированных контрольных запусках при ещё занятых worker и живом дочернем
процессе. Это измерение данной проверки, не универсальная гарантия задержки.

Отдельно прошли VLESS, VMess, Trojan, Shadowsocks, Hysteria2 и TUIC под обычным
пользователем: локальная готовность ядра, аутентификация контроллера, Unicode и
полная очистка. WPF smoke подтвердил отрисовку, повторное открытие и сохранение
настроек. Приёмка публичной связности и Windows 11 остаётся отдельной задачей.
Предыдущие неудачные прогоны сохранены в `NODE_RUNTIME_ENTRY_VALIDATION.json`;
историческая причина отказа порта не установлена. Следующий ограниченный шаг —
аварийное завершение чтения валидатора и тестового сервера, затем передача узла
службе. Кандидат V3H остаётся отдельным пакетом.

## Windows-пакет

В отдельной разработческой поставке запускается `desktop/AutoVpn.Desktop.exe`.
Архив самодостаточный, но не является установщиком или готовым VPN.
Текущий V3 workflow создал новый development-пакет на Windows и отдельно
проверил WPF на Windows Server. Сам распакованный архив отдельную приёмку
не проходил; его байты здесь независимо не проверялись.
Не запускайте лабораторную установку службы на рабочем компьютере,
не отключайте антивирус и проверку подписи драйверов.

Не повторяйте исторические одноразовые скрипты интеграции и консолидации.
Гроку остаются сборка/проверка, не незавершённая реализация.
